- バックアップは `.private/save-backups/` に新規コピーし、`.private/` をgitignoreへ追加。実セーブをfixture、レポート、配布ZIPへ含めない。Downloads側の元出力は削除していない。

- 初回の複製ロード確認はCloud上書き警告によりキャンセル。その後ユーザーが複製スロット2のロード/Cloud同期を明示許可し、開発用profileを選んでロード。元スロット1はロードしていない。ゲームの通常autosaveにより複製側の保存日時/profile表示は更新された。

- local modの初回登録で予約namespaceを拒否。manifestを`autopilot`へ修正し2ファイルだけのZIPを再生成、ソース一致を検査。再選択時の古いFile参照読取りエラーは、新しいZIP名で選択し直して登録成功。コード起動/UI試験の結果は別途記録する。
- 旧local登録は無効化して保存し、最新ZIPを`Melvor Autopilot v0.1.0 Current Analysis`として新規登録。既存登録のUpdate Modfileで表示修正が反映されない理由は未確定。最新登録の明るいdiv logは視認確認済み。
- 最新登録で初期停止→解析開始（runtime-adapter-unverified）→手動停止を確認。JSON出力はapp/version/logs、4件のtimestamp/messageと固定順序だけを検査し、`reports/p0-ui-2026-10-12.json`へローカル退避。ログにセーブ/認証/キャラクター名は含めない。最終状態は停止中。

## 照合記録の形式

実機試験は1つのAPI/通常操作から順に行う。記録するのは検証日、ゲーム版、モード、所有スコープ、API名、対象ID、必要な数値/フラグ、前後の判定、固定理由、UIとの一致だけ。

セーブ文字列、認証情報、Cloudアカウント情報、キャラクター名、例外本文を記録/外部送信しない。実機で不一致・他MOD競合・不明状態が出た場合は操作を止め、該当APIの未検証状態を維持する。

個別結果は `API_EVIDENCE.md` と `TESTING.md` に記録し、この表の実機状態を証拠付きで更新する。全カテゴリ/DLCの欄が揃うまでP5達成と扱わない。
